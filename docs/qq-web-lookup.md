# QQ 数码问题联网查询（2026-11-02）

保留现有 QQ 接入、回复模型、人格和群/私聊开关，修复 Gemini 文字通道过度依赖模型主动发搜索标记的问题。

- 当前价格、在售型号、硬件配置、系统版本、兼容性、购买推荐和型号比较等数码请求先查询，再调用现有模型作答；明确说“联网查/查一下”也可触发。普通闲聊、历史偏好回忆不预查，明确不联网时不搜索。
- 其他问题仍可由模型调用既有搜索工具；兼容单独工具标记及 QQ 动作 JSON 的 reply 字段，不执行中间搜索计划附带的其他动作。
- 沿用现有 DuckDuckGo 公开搜索，不新增密钥、浏览器或常驻进程。优先官方结果，最多并行读取两个已列明厂商的公开页面补充正文；页面读取禁重定向、限大小，网络共用原12秒期限。
- 查询缓存按机器人账号和会话隔离，5分钟有效、最多64条，并发相同查询复用；“刷新/重新查/实时”要求跳过缓存。保留原获取时间，不把缓存命中时间当新查证时间。失败不缓存。
- 给模型的网页资料总量有界，网页文字是参考数据而非操作指令；只附真实结果中的链接。搜索失败或无结果必须说明无法确认，不凭模型记忆编造当前价格/版本。价格须区分地区、币种、容量档位和促销。
- QQ 输出自动补充1–2个实际来源链接；带链接的结果沿用原有文字发送策略。生图与普通图片识别路径不替换；本次不是“图片识别后任意多步浏览”的新增工作流。
- 草稿API结果的 `webLookup` 记录查询、获取时间、缓存命中、状态及真实资料。不开新群AI，不改变此前38开/14关的批量设置，不发送额外测试群消息。

源码：`src/qq-web-lookup.mjs`、`qq-text-context.mjs`、`server.js`。验证文件：`verification/qq-web-lookup-20261102/`。发布沿用 `node scripts/deploy-local-services.mjs`，空闲后只需重启 chat-hub；QQ 登录与消息桥接不必重启。升级前版本见 before.json，回滚切回该 service-code 并重启 Hub，保留共享 data。
