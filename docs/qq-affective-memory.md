# 情感与记忆联动

本模块是在现有 QQ 群友中独立实现的轻量机制。截至本次开发，视频 BV1syHw6qEqW 的简介没有提供 Campanula 源码链接，公开同名仓库也未确认对应项目。因此不能声称已移植或精确复现 Campanula 的原始代码/算法；获得原项目地址后才能逐项核对。没有引入其他 QQ 客户端、进程、向量服务或浏览器回复。

## 目前的闭环

- **经历 → 记忆**：合并现有后台抽取调用，要求逐字原话证据、稳定主题、重要程度和可选的三维情绪。重要程度看未来用途，不把负面或激烈等同于重要。
- **当前情绪**：效价、唤醒度、掌控感，平滑更新，六小时指数衰减；只作语气弱参考，当前表达和自定义人设优先。
- **按需召回**：先限定本人和当前会话，做全文相关性检索，再以重要程度、时间、不同来源的重复确认及弱情绪相关性调整相关候选的次序。主题匹配的权重大于情绪加权，不因心情低落翻出无关旧事。
- **长期保留**：时间衰减只影响召回次序，不自动删除长期事实。相同来源不会重复增加确认次数，纠正使用同一事实键；更晚的管理者纠正不会被更早的待整理原话覆盖。
- **可撤销**：忘记同时清掉记忆、检索、情绪附属数据和可复活旧记忆的派生片段；不删 QQ 原聊天。新话题保留长期记忆。
- **可查看**：本机记忆接口返回当前用户的情绪参考；`/emotion`、`/情绪` 查询自己的近期参考，仍经过群白名单、私聊权限和会话 AI 开关。

## 资源及边界

新增一张小型 SQLite 元数据表和一个情绪字段。沿用每次最多八条消息、最多四条事实的后台合批；不增加模型请求次数/频率，不在普通回复前等待情绪抽取。分析失败退回普通回复，生图路径不注入这些记忆和情绪。

抽取提示增加少量字段，因此每个后台批次的 token 会略增，并不等于零成本。后台分析同样计入既有用量账本。没有无限记忆/完整记忆承诺；原始派生片段仍滚动保留，正式长期事实持续存储，除非明确更正/删除或约定到期。
