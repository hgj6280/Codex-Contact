# QQ 群友：接话、资料库与发言节奏（2026-11-01）

参考 yonagi-speak，在现有 Node / QQ 接入上实现；没有安装另一套机器人、替换人格或新增模型进程。保留上游 [MIT 许可证](licenses/yonagi-speak-LICENSE.txt)。借鉴的是按群隔离的文档检索、结合连续发言理解转折与评价对象；当前代码是对现有架构的独立适配，不宣称复刻上游全部功能。

## 日常使用

狐宫静 QQ → 设置 →「自主聊天与操作权限」→「参与群聊的节奏」：可调参与强度、主动开话题、引用和 @ 概率；高情商接话、持续聊天规划、动态节奏、额外冷却可分别开关。普通回复默认不 @。这些概率用于可参与机会，**不是每收到一条消息就独立抽一次**。明确 @、触发词、私聊的正常请求不受随机插话门槛影响，原会话 AI 开关仍优先。

本次低频配置：参与强度 0.03、另开话题 0.05、普通自主回复引用 0.1、自动 @ 0；额外冷却 90 秒，每群自主接话每小时最多 8 轮。正在进行的对话仍可自然接续，受既有短间隔、作息和限额约束。

设置 →「发言额度」：机器人账号全项目每日最多 2000 次消息发送尝试，可进一步调低；默认每分钟最多 20 次。群、私聊、自动/手动、文字/语音/图片/视频任务结果、长回复每一段都经过原 QQ 桥接的统一入口。限额拦截不自动重试；时间按 Asia/Shanghai，每日零点重算，重启不清零。超时/失败/启用前日志回补保守计数，可能比实际成功条数多。其他 QQ 客户端无法由本项目拦截；2000 不是腾讯保证安全的阈值。

需要长回答时直接说「用文字盘点十项」「详细展开」「回复长一点」。本轮长度要求优先于日常短句偏好和普通语音模式；长正文完整保留，按约 1800 字符分段，不在 1000 字处截断。单次仍有防异常输出的 18000 字符上限；供应商自身输出/超时限制依然存在。普通闲聊不因此变长。明确朗读仍使用原语音功能。

## 资料库

先选择会话，再在设置 →「资料库」新建或导入 UTF-8 TXT / Markdown。文件先预览，点击保存才入库。默认仅当前群/私聊可用，只有明确选择共享的资料才用于所有会话；QQ 账号之间也隔离。会话可单独关闭检索。

每篇最多 20 万 UTF-16 字符、每账号 200 篇/200 万 Unicode 字符；本地 SQLite FTS 分块按词检索，最多带 3 段、默认合计约 1100 字符，可调到 2200。命中时适当缩减其他近期/长期提示片段。没有新增 embedding 模型、网络请求或常驻服务。词片检索不等于任意措辞的语义理解，标题/正文应包含实际会问的名称。

更新/停用/删除下一轮立即生效；按版本校验防覆盖，每账号保留最近 20 个修改/删除前版本。聊天记录与角色库不迁移。资料是参考数据，不能授权 QQ 操作或改变人物权限。界面仅本机管理，模型和群友不能任意指定 QQ 身份、会话或服务器文件路径。草稿结果的 `knowledgeReferences` 可核对命中的资料段。

## 文件、启动与回滚

当前服务使用既有 Node 24.15，本次无新增 npm 依赖。源码 `src/qq-knowledge*.mjs`、`src/qq-dialogue-context.mjs`、`src/qq-send-budget.mjs`；前端编辑器在 `modules/web-console/public`。共享运行数据 `~/Library/Application Support/CodexRemoteContact/data/qq-knowledge.sqlite`、`qq-send-budget.sqlite`。资料迁移请先停服务，连同 SQLite 的 WAL 文件一起备份，保留原 data 目录；不要只复制一个运行中的 sqlite 主文件。

发布前确认桥接 `/health` 和 `/api/qq/chat/desktop-state`、视频任务队列、语音均空闲。首次升级可先 `node scripts/seed-qq-send-budget.mjs` 预览日志回补，再加 `--apply` 执行（只计数，不复制聊天内容；同日重复执行不重复加数）。然后：

```sh
node scripts/deploy-local-services.mjs
launchctl kickstart -k gui/501/local.codexremotecontact.qq-napcat
launchctl kickstart -k gui/501/local.codexremotecontact.chat-hub
```

无需重启原生 QQ。本次升级前版本路径见 `verification/yonagi-20261101/before.json`。回滚时将 `service-code` 原子切回该版本并重启上面两项，保留共享 data。旧版没有新限额与资料库功能，不要把回滚后的旧服务当作已受新限制保护。测试与实际联调记录见同目录验收文件。
