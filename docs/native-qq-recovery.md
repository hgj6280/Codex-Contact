# 原生 QQ 离线恢复（2026-11-02）

本次发现：QQ 自身状态离线时，OneBot WebSocket 与 Node 服务仍可运行。原生连接日志多次出现 `重启功能未初始化`，原 Worker 恢复没有实际执行。11 月 1 日 17:34 另有明确的登录凭据失效通知；21:05 和 11 月 2 日 03:16 的离线只有状态变更，没有能确认最初原因的错误码。两段附近没有查到匹配的 macOS 睡眠日志。用户确认未同时登录其他电脑客户端。不能据此声称所有掉线都由睡眠、网络、异地登录或 QQ 风控造成。

修复沿用现有桥接进程，每 30 秒检查真实 `get_status.online`，不以 TCP/WebSocket 连接或 `good` 判定 QQ 在线。持续确认离线 90 秒后，只重启 `local.codexremotecontact.qq-native` 这一项。单次临时断线、无法确认状态、仍在线、非原生配置均不重启；不启动虚拟机、不修改日常 QQ、不改变人设/模型/AI 会话开关。

每次恢复尝试先原子持久化到共享 data 的 `qq-native-recovery.json`，再执行固定参数的 launchctl。最短间隔 5 分钟，每小时最多 2 次，重启桥接不清零。现有原生请求未结束时暂缓恢复。状态损坏/无法持久化则停止自动重启。

发现新二维码后进入 `awaiting_scan`，停止自动重启，等待手机确认；二维码过期由原登录服务刷新，不靠持续杀进程。只有真实在线状态才能离开等待扫码状态。登录授权失效仍需要本人确认，无法保证永不掉线或绕过 QQ 登录。

桥接 `/health` 分别给出 `connected`、`qqOnline` 和 `nativeRecovery`；控制台通过 `/api/qq/chat/desktop-state` 读取恢复状态。`connected=true` 只代表本机 WebSocket。软件的“扫码登录”仍打开原 WebUI，同时调用本机受限的 `/api/qq/chat/recover-login`，已在线时不会重启；手动请求也受恢复预算约束。接口只作用于固定原生服务，不能传命令、路径、账号或群目标。

确认离线时，发送与图片/引用等需要 QQ 登录的请求快速返回 `QQ_OFFLINE`，避免继续向离线内核堆积下载请求；不重试不确定发送，不重置每日 2000 条限额。正常聊天、原有生图和语音流程不替换。

发布仍用 `node scripts/deploy-local-services.mjs`，空闲后重启桥接与 Hub。验证原生在线状态、恢复状态以及后续实际收发，不把测试通过或进程存活当作 QQ 已恢复。本次证据在 `verification/native-recovery-20261102/`。如回滚，仅切回升级前 service-code 并重启这两项，保留 data 和原生账号目录；旧版不具备此次自动恢复。
